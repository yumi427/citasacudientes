🚀 Flujo de Entrada: Desde la Carga Web hasta el Guardado en Base de Datos
Haz clic en un paso para resaltar los componentes en el diagrama
1
Descarga PWA
Usuario abre el navegador móvil → CloudFront sirve SPA desde S3 mediante OAC cifrado con TLS 1.3 y SSE-KMS.
2
Solicitud HTTPS
Acudiente selecciona cita → Envía POST /citas con payload JSON cifrado en tránsito por TLS 1.3.
3
Gateway & Enrutado
API Gateway valida esquema JSON, verifica CORS/Auth y deriva mediante conexión interna TLS a AWS Lambda.
4
Lógica & Validación
Lambda procesa la regla de negocio y prepara la transacción atómica para garantizar cupo único.
5
Escritura Transaccional
Lambda invoca TransactWriteItems sobre DynamoDB vía SDK HTTPS TLS 1.3 sin streams intermediarios.
6
Persistencia KMS
DynamoDB cifra en reposo con AWS KMS (256-bit) y retorna 201 Created al celular del acudiente.
🔒

Cifrado en Tránsito (End-to-End TLS 1.3)

Todo paquete de datos viaja bajo canales criptográficos seguros: Móvil ↔ CloudFront (HTTPS TLS 1.3 con certificados ACM), CloudFront ↔ S3 (HTTPS con OAC estricto), Móvil ↔ API Gateway (HTTPS REST), y Lambda ↔ DynamoDB (Llamadas API al endpoint regional con TLS 1.3).

🛡️

Cifrado en Reposo (AWS KMS con Claves Administradas)

Cero datos en texto plano: Amazon S3: Cifrado del lado del servidor SSE-KMS en cada objeto estático. Amazon DynamoDB: Cifrado en reposo habilitado con AWS KMS (Customer Managed Key), cifrando tablas, índices (GSI) y copias de seguridad. AWS Lambda: Variables de entorno y artefactos cifrados con KMS.

Seguridad Transversal con AWS IAM & Mínimo Privilegio

Cada Lambda cuenta con un Execution Role aislado: únicamente permisos de escritura transaccional sobre CitasAcudientesTable y uso de la clave kms:Decrypt / kms:GenerateDataKey. S3 bloquea acceso público mediante política OAC.
